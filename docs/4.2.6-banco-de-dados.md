# 4.2.6 Modelagem de Banco de Dados

Das classes às tabelas

Cada classe principal do sistema VelocityGames foi transformada em uma tabela no banco de dados. Seus atributos foram convertidos em colunas, e as associações foram representadas por chaves estrangeiras (FK).

O banco de dados do VelocityGames é composto por cinco tabelas principais: jogo, exemplar, cliente, administrador e emprestimo.

A tabela jogo armazena os títulos, as plataformas e os anos de lançamento. A tabela exemplar registra as unidades físicas de cada jogo e sua disponibilidade. A tabela cliente guarda os dados dos clientes cadastrados, enquanto a tabela administrador identifica os atendentes responsáveis pelas operações.

A tabela emprestimo registra os aluguéis, relacionando o cliente, o exemplar e o administrador responsável, além das datas de retirada, previsão de devolução e devolução efetiva.

Os relacionamentos funcionam da seguinte maneira:

Um jogo pode possuir vários exemplares, mas cada exemplar pertence a apenas um jogo.
Um cliente pode realizar vários empréstimos, mas cada empréstimo pertence a apenas um cliente.
Um administrador pode registrar vários empréstimos, mas cada empréstimo possui apenas um administrador responsável
