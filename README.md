## Apresentação do projeto

O **VelocityGames** é um sistema de gestão desenvolvido para otimizar o controle de acervo e o fluxo de aluguel de jogos de corrida e consoles retro e modernos. 

O proprietário enfrentava problemas semanais com o controle manual de empréstimos, perda de prazos de devolução por parte dos clientes e falta de histórico de disponibilidade das mídias físicas na estante. 

O sistema automatiza o cadastro de exemplares, a consulta de disponibilidade por console ou época, o registro de empréstimos vinculados aos clientes e o cálculo automático das datas de devolução, garantindo organização operacional e eliminação de atrasos não identificados.

## Como este repositório funciona

Cada seção do documento mora num arquivo dentro de `docs/`, com o número do modelo do IFPR no nome. Não renomeie esses arquivos. É pelo nome que a correção localiza cada seção.

As seções entram uma por aula. Enquanto a vez de uma seção não chega, o arquivo dela mostra um cadeado 🔒. Na aula, o molde chega pelo AVA junto com a mesma seção pronta do BiblioTech.

Os diagramas vão para `diagramas/`, sempre em dois arquivos com o mesmo nome:
* O `.drawio` serve para editar.
* O `.png` aparece na página de documentação.

As telas do protótipo vão para `prototipos/`.

## O exemplo do BiblioTech

A pasta [`exemplo-bibliotech/`](exemplo-bibliotech/) tem as seções do BiblioTech já resolvidas, com os mesmos nomes de arquivo do seu `docs/`. Quando travar, abra a seção do BiblioTech ao lado da sua e verifique o que foi feito naquele ponto. Copiar a frase trocando o nome do sistema não conta como seção feita.

O exemplo cresce a cada aula no [repositório do modelo](https://github.com/Profe-Berssa-IFPR/2026-APS-modelo/tree/main/exemplo-bibliotech). A cópia que veio para o seu repositório para na seção que existia no dia em que você o criou. Para ver as seções novas, consulte o repositório do modelo.
